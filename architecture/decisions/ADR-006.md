# One public contract version

## Decision and rationale
All public authoring and exchange objects use `archctl.*.v2`. The advisory
family moves from `contracts/context/v1` to `contracts/context/v2`. Legacy
authoring v1 and its runtime migration command are removed after the 0.3.0
migration bridge. Persisted memory records move to `archctl.memory.v2` through
a one-time serialization migration.

The governed and advisory families remain independent. They keep separate
directories, generators, parsers and consumer promises. The shared version is a
single compatibility label, not a merged responsibility or schema generator.

## Compatibility
ADR-005 still governs the default advisory workflow and its separation from gate
authority. ADR-002 still governs the optional governed gate. Gate semantics,
exit codes and the distinction between passed, failed, unknown and not_executed
do not change.

Additive fields stay within v2. A breaking change to either public contract
family advances the shared version for all public contracts. Version labels do
not couple the two families' runtime behavior.

Users with v1 authoring intent run `archctl model migrate` from 0.3.0 before
upgrading. Users with v1 memory records run the one-time migration script. The
0.4.0 CLI rejects both rather than silently converting them.

## Alternatives
Keeping separate v1 and v2 labels preserves independent release cadence but
leaves two consumer models. Renaming the governed v2 contracts down to v1 reuses
a label with incompatible authoring and adapter history. Merging the two schema
families would couple gate changes to advisory output beyond the shared version
decision.
